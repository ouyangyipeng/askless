# AskLess 架构与边界

## v0.3 文件预览与条件决策

`sdk.py` 新增不可变的 `DecisionProgress`。每次用户回答后，保留符合已确认答案的
完整分支集合，再比较剩余选择。该步骤复用原有证据；全部必要选择确定后才重新
执行一次最终策略。原来的 `Exploration.resolve` 接口保持兼容。

`exporter.py` 提供 `file-export/v1`：扁平 JSON 数据可导出为 JSON 或 CSV，CSV 可选择
分隔符与列名。八个组合完整执行。用户选择 JSON 后，两个 CSV 相关选项在剩余
分支中结果相同，因此自动消除。

`snapshot.py` 保存有版本的输入、合同与完整执行矩阵。恢复时校验作用域、策略空间、
唯一分支、结果哈希和大小预算。`decision_sessions.py` 将快照、按顺序记录的回答、
revision、事件、模型用量和最终产物保存到独立的 `decisions.sqlite3`。

浏览器以 `input_text` 原文提交数据，由后端严格解析，保留超出 JavaScript 安全整数
范围的 ID 并拒绝重复字段；`inputs` 接口仍可供已有调用方使用。显式新建使用新的
创建请求 ID，同一次失败重试保留原 ID。

```text
Python Agent → MCP preview_export → ready
                                      │ 工作台逐项选择
                                      ▼
                                   chosen
                                      │ MCP collect_export
                                      ▼
                      校验当前输入 → 复算 → completed
                             │        │
                             ▼        ▼
                           stale    failed
```

创建和回答使用幂等键，状态变更在 `BEGIN IMMEDIATE` 事务中检查 revision。记录模型
用量不改变决策 revision，避免后台用量写入使刚显示的选择失效。源文件在接受回答和
完成前重新读取并核对规范化 JSON 哈希。过期输入停止交付；已完成产物可重复读取。

`mcp_server.py` 的 stdio 服务绑定启动参数中的一个文件；工具返回状态、待定键和
本地链接。`agent.py` 是两阶段参考宿主：模型选择经过严格参数校验的工具动作，
随后通过真实 MCP 客户端执行。原始记录只在本机预览，模型收到任务、工具定义、
聚合统计和已确认选项。HTTP 不接受源文件路径。

参考宿主的模型阶段按数据目录串行执行，占用独立 SQLite 事务锁。并发调用在发出
模型请求前返回忙碌状态；进程退出自动释放锁，工作台回答使用另一数据库，不受阻塞。
已有创建请求会复用经过校验的会话，恢复时复用已保存的模型动作。

`/decisions` 展示真实文件内容、逐项选择、自动消除结果与执行证据；`/api/decisions`
复用现有同源及 token 检查。文件会话与联系人工作台分别保留 50 条记录、两个未完成
会话和每条 8 MiB 上限。接口与恢复步骤见 [Agent 工作流](agent-workflow.md)。

## 信任与数据路径

浏览器经同源 API 访问 FastAPI。服务只监听本机，Host 检查限定 `localhost` 与 `127.0.0.1`；写入需要本机会话 token，并检查有 Origin 的请求是否同源。模型凭据保存在后端进程环境中。

模型生成问题措辞与角色说明，操作语义来自程序中注册的 `DecisionSpec`。每个角色必须提交 `duplicates`、`invalid`、`email_case` 各一项，缺项、重复或额外字段均拒绝。程序为问题设置角色 ID、合同键与数据哈希。模型无法提交 shell 命令、修改操作选项或选择任意执行目标。

三个二值合同构成八个 `Policy`。执行器将每个策略应用于完整数据，保存 `Evidence`：策略、导出记录、隔离记录、阻断状态、重复数、耗时和结果哈希。列名和序列化大小限制在执行前生效。

## 编译与传播

编译前校验所有问题与证据的作用域一致、问题 ID 唯一，以及八个策略组合完整且无重复。相同合同下的问题合为一组。对每项合同，固定另两项策略形成四对结果；四对都等价才自动解决。任何一对存在差异，则保留这项人工决定，展示一对真实差异证据。

回答接口要求提交全部且仅提交待定合同。SQLite 的 `BEGIN IMMEDIATE` 事务检查状态与 revision，验证选择合法，计算最终策略并进入 `applying`；同一事务内执行活动运行上限检查。重复提交、过期版本或并发名额不足返回 409，保存的数据不发生部分修改。

每个角色随后收到完整已确认策略，必须显式回传全部字段且值一致。程序按相同策略重新执行，输出哈希一致才保存回执。三个角色全部成功后，运行才进入 `completed` 并允许下载。任何角色失败会保留已有证据并标记失败。

这三次重新执行使用同一个确定性 CSV 实现，用来确认各角色传播的是同一份策略；它们共享该实现的行为边界。

## 状态机

```text
planning → exploring → ready → applying → completed
   │           │                   │
   └───────────┴───────────────────┴──→ failed

planning / exploring / applying ── 服务停止或重启 ──→ interrupted
```

`ready` 的选择跨重启保存。中断运行保留已经完成的部分，不自动重放可能产生费用的 LLM 请求。历史元数据查询不加载全部分支对象；数据库连接在每次事务后关闭。

前端通过运行 ID 和视图版本绑定异步结果。切换运行或新建视图后，旧请求的返回不会覆盖当前页面。已确认选项始终读取服务端保存的 `group.selected`。

## API

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/config` | 模型名、配置状态、本机会话 token、示例输入 |
| `GET /api/runs` | 本地历史元数据 |
| `POST /api/runs` | `{title, csv_text, mode}`；创建并开始提问 |
| `GET /api/runs/{id}` | 完整状态、问题、分支、回执 |
| `POST /api/runs/{id}/answers` | `{answers, revision}`；原子确认并恢复执行 |
| `GET /api/runs/{id}/export` | 已完成且未被阻断时导出 UTF-8 BOM CSV |
| `GET /api/runs/{id}/evidence` | 完整 JSON 证据包，包含原始 CSV 解析数据 |
| `DELETE /api/runs/{id}` | 删除非活动运行 |

写入请求携带 `X-AskLess-Token`，服务重启后应刷新页面取得新 token。错误返回 `{detail: string}`。LLM 的 HTTP 状态与安全错误类别可进入响应，供应商错误正文、认证头和凭据不会写入运行记录。

## 资源预算

输入上限为 256 KiB / 2,000 行 / 30 列，单个列名 128 UTF-8 字节，展开数据 512 KiB。一个运行最多存储 8 MiB；最多 50 次历史记录与两次活动运行。模型请求每个阶段三路并行，单次最多两次尝试。

当前实现完整持久化八份证据，适合有界实验。后续适配器若有更多选择，需要显式定义探索预算、未覆盖组合的状态和结果保留方式；自动解决仍需要满足适配器声明的比较条件。
